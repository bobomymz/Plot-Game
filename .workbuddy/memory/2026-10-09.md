# 2026-10-09

## CI 排查：Actions「No jobs were run」（与改 GitHub 密码无关）

波波报：定时推送（AutoPushGame）像出问题了，怀疑跟刚改 GitHub 密码有关。

**根因**：`deploy-cloudflare.yml` 里 `if: ${{ secrets.CLOUDFLARE_API_TOKEN != '' }}`
—— GitHub 硬规则「**secrets 不能直接出现在 `if:` 中**」（官方文档原文，Using secrets in GitHub Actions）。
一旦这么写，**整个 job 不创建**，workflow 判 failure 但无任何 job → 只显示 "No jobs were run"。

**排除密码嫌疑的三项证据**：
1. `GET /actions/runs/<id>/jobs` → `total_count: 0`（job 一个都没建，不是执行失败）
2. 该 workflow 自 2026-10-02T01:00 首次运行起 **15 次运行 0 成功**，早于改密码
3. 期间 AutoPushGame 的 `push` **一直成功**（push-log.txt 全绿）；失败发生在服务端解析 workflow 阶段

**修复（commit `0850f64`，已推送）**：secret 提到 job 级 `env` → `if: ${{ env.CF_API_TOKEN != '' }}`。
验证：修复前 jobs=0/failure，修复后 **jobs=1/success**（Setup→Checkout→Node→Build 全过）。

**遗留（第二个独立问题）**：`CLOUDFLARE_API_TOKEN` 仍未在 GitHub 配置 →「提示：缺少 Secret」步骤被执行、
`Publish` 被 skip。构建链路已恢复，**云端上传仍未启用**，需波波配 Secret（待拍板）。

## 顺带发现：HTTPS push 被代理搞坏

改密码后 git push 卡死。实测：`github.com` 经代理（`http://127.0.0.1:7892`）→ **502 CONNECT tunnel failed**；
直连 → 超时；`api.github.com` → 200 正常。
绕过：**`git@ssh.github.com:443` 可用**，本次推送走
`git push git@ssh.github.com:bobomymz/Plot-Game.git main`。
⚠ `origin` URL 未改（仍是 https），**AutoPushGame 走 https，代理修好前会继续失败**——待波波拍板。

## 坑记录

- ⚠ **`secrets` 不能放 `if:`**：job 直接不创建，报错文案是 "No jobs were run"，
  看着像「调度失败/权限问题」，实际是**语法非法**。排查关键是查 `/jobs` 的 `total_count`——
  为 0 就是 job 没建（语法层），非 0 才是执行失败。
- ⚠ 判断 GitHub 侧问题优先用 `api.github.com`（本机可达），别拿 `github.com` 的 502 当依据。

## 代理是间歇性的（波波 21:26 实测）

波波在任务计划程序里手动跑了一次 AutoPushGame，**成功上传**（`27c311c..566945a`）。
