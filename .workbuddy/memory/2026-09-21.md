## 背包容量体系改造落地（用户定案：一个主背包 + 一个袋子）

**用户设计**：正常最多带「一个包 + 一个袋子」（再多没手对付丧尸）。默认小背包容量 3；包不分种类但分容量，可换大包；袋子（帆布袋）统一命名，持有即 +1。

**改动清单**：
- `core.js`
  - `bagVolume` 从普通变量改为 `_reactive.computed` 派生式：`3 + _bagTier + _bagExtra`（第 343 行）。剧情代码不再直接改 bagVolume。
  - 新增 4 个变量：`_bagTier: 0`（0默认/1双肩包/2书包）、`_bagExtra: 0`（袋子加成）、`hasBackpack`、`hasSchoolbag`。
  - 整理整理「丢下帆布包」→「丢下帆布袋」，副作用 `add: { bagVolume: -1 }` → `add: { _bagExtra: -1 }`。
- `安居苑.js`
  - 新增主背包：`三林安居苑-8号楼-203室-双肩包` 增加「背走这只双肩包」选项（闸门 `vars._bagTier < 1`）+ 新结果场景 `-背走双肩包`（`set: { hasBackpack: true, _bagTier: 1 }`）。
  - 卧室「拿上帆布包」→「拿上帆布袋」，`bagVolume:+1` → `_bagExtra:+1`。
- `建平中学.js`
  - 新增主背包：`建平-挹芬楼-3F-高一教室` 增加「从地上捡一只书包」选项（闸门 `vars._bagTier < 2`）+ 新结果场景 `-捡书包`（`set: { hasSchoolbag: true, _bagTier: 2 }`）。
- `新达汇.js`：`帆布包` → `帆布袋`（场景 ID `新达汇-2F杂物间-帆布包` → `-帆布袋`），副作用改 `_bagExtra`。
- `安盛街.js`：帆布袋入口副作用改 `_bagExtra`，系统提示补「获得帆布袋」。

**关键设计点（与用户原方案的偏差，已确认合理）**：
1. 用户说「若当前容量 >= 可更换的包的容量就不显示」——但包本身不占容量（是容器），所以**闸门改用 `vars._bagTier < N`**（当前档位 < 该包档位才显示），避免"已背书包还提示换双肩包"。
2. 用 `set: { _bagTier: N }` 而非 `add`，天然实现「换包是换不是加」。双肩包→书包 得到 5 而非 6。
3. 三处帆布袋入口**不再互斥**（这是原缺陷的根因），但仍共享 `hasBag` 所以只能拿一个（符合"只能带一个袋子"）。

**容量上限**：书包5 + 帆布袋1 = 6 格（原为 4 格）。
