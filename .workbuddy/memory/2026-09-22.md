## 排查：控制台改 `gameState.weather` 为何会被"还原"
- 用 `tools/test_helper.mjs`（Playwright E2E）写临时探针实测，结论已确认，探针脚本已删。
- **写入本身是生效的**：`weather` 是 core.js `_variables` 里的普通变量，同小时内连续走 20 步都保持 `雨`。
- **真正的改写方只有一个：`utils.js:86 updateWeather(vars)`**，由 `utils.js:29 updateTime` 在「跨整点 `hh` 变化」**或**「单步 `mins >= 60`」时调用。实测 8:42→9:08 一步就触发，`雨 → 阴`（50%）。
- 概率表（实测吻合）：雨→50% 阴；阴→(6-11点)30% 晴 /(12-17点)35% 雨；晴→(12-17点)30% 雨 /20% 阴。**雨的唯一出口是阴**，所以特别像"变回原来的天气"。
- 全库时间步长分布：1min×1200、2min×408、3min×107、5min×77、10min×31、30min×22、15min×15、180/120 各 1 —— 道路长段多，跨整点常见。
- **第二个坑（视觉）**：`engine.js:1148` 每个场景无条件把 `showRain=false`，且雨天 CSS 类条件为 `weather=="雨" && showRain`（core.js:519）→ 即使 weather 还是雨，走出下一步雨滴动画也会消失。
- 附带：户外场景 `engine.js:1160` 自动 `applyWeatherDrain()` → 扣体力 / `_rainExposure +20`，测试时会看到意外掉体力。
- 测试雨天建议：`gameState.weather='雨'; gameState.showRain=true; applyScreenEffects();`，并注意回溯/读档后 `gameState` 会换成新 Proxy 对象，挂在其上的 defineProperty 锁会失效。
