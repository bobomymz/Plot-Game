## 车库密度描写·视觉档（10-03，对标 describeZombieWave）
波波提议"车库也该有提示尸潮密度的描述语，只在手电/通电时给"。**三岔路拍板：①邻格只报最危险那一格 ②报程度不报数字 ③全黑不给邻格提示**。已实施。

- **关键前提**：车库**不是从零加**——`xdGarNoise` 早已按当前格密度分 3 档，但全是**听觉**描写（水声/拍水声）且不分光照。所以新做的是「补视觉通道 + 按光照分流」，不是替换。

## 过夜系统「过程性节点」问题（10-03 晚，波波提议引发，已核实未实施）

### 核实结果：问题真实且**比驾驶那一例严重得多**
- **机制**：`_globalTriggers` 里 `{ condition:"hh >= 19", targetScene:"天黑必须过夜", priority:5 }`，在 `renderScene` 的 **checkGlobalTriggers(1541)** 检查。
- **用真实 renderScene 实测**（vm 沙箱 DOM 桩足够跑通）：**103 个带 `qte` 的场景，100% 在天黑时被直接弹到「天黑必须过夜」**，一个都不剩。其中包含全库 47 场闪色战斗（`flashCombatRouter` 共 57 处引用）。
- 所以不止"车停半路"：**任何在 19 点前一刻进入的必打战斗都会被整场吞掉**（玩家少经历一场本该必打的战斗，叙事缺口）。
- 驾驶那一例只是其中一种表现（只是它还会把 `_driving` 泄漏到第二天）。
- 唯一现有豁免：`engine.js:1538` 的 `isEndingScene`（"结局"前缀 或 静态文案含"—— 结局："）→ 结局终态不响应触发器。

### 我的方案评估（待波波拍板，尚未改代码）
- 波波的"加变量"**技术上可行**（trigger condition 是字符串，能读任意 gameState 键）。
- **但我不建议**：豁免是**「当前节点的属性」，不是「玩家的状态」**。用状态变量表达位置属性，必须维护"进入置位 + 所有出口清位"，而出口有四路（正常选项 / QTE 超时 / 全局触发器跳转 / 回溯·读档）——这正是刚修完的 #3 bug（`_driving` 泄漏到第二天）的成因，同样的坑会再踩一遍。
- **推荐改为场景静态属性 `scene.nightImmune`**（布尔或函数），引擎在 checkGlobalTriggers 处跳过。优点：零状态、零清理、**回溯/读档天然正确**（属性不在存档里）、lint 可静态检查。
  函数形态可批处理：`nightImmune: function(v){ return !!v._driving; }` 一次覆盖车库九格。
- ⚠**豁免是安全的**：它只是"延后"，玩家一旦走进任何非豁免场景就会被抓去**收敛**，不会卡住；死亡结局本来就豁免。
- 待波波定的范围：A 只豁免过程态（驾驶） / B 过程态 + 所有 qte·战斗场景（推荐，规则统一免逐个标） / C 逐场景显式声明。
