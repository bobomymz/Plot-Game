# Design

## Context

现状（动机见 proposal.md）：

- `engine.js` 渲染场景图在 `renderScene` 中（engine.js:1049-1061）：`#scene-image` 单元素，桌面 `object-fit: cover`（裁切），手机 `contain`（缩小）。**图片区当前没有任何点击绑定**——打字机跳过/文本展开绑在 `#sceneText`（engine.js:154），所有屏幕特效遮罩均为 `pointer-events: none`，点击可穿透到图片。
- z-index 体系（CLAUDE.md 层叠顺序表）：特效层 50、文本/选项 60、文本展开 100/101、状态栏 120、QTE 条 150、预加载 9999、存档弹窗 10000。
- 手机端布局关在 `@media (max-width: 767px)` 内；设备判定惯例：布局跟宽度、hover 跟 `@media (hover: hover)`、输入方式跟 `IS_TOUCH`（见手机端适配.md 第二节）。
- 引擎已有"每场景重置 UI 态"惯例（`showRain`/`showZombies` 每场景清零）和"换场景内部滚动回顶"先例。
- 项目零依赖、无构建步骤，所有交互必须用原生 JS/CSS。

## Goals / Non-Goals

**Goals:**

- 标记场景图点击打开全屏查看器，contain 完整显示，滚轮/捏合缩放（fit ~ 4×），拖拽平移，单击/Esc 关闭。
- 与 QTE、记忆闪色、场景切换、存档体系正确协同（见 specs/image-viewer）。
- 双端共存：手机专属样式全部关在媒体查询内，桌面逐像素不变（除标记场景的角标与光标）。

**Non-Goals:**

- 早期 0.75 比例场景图的重新生成（作者另行用图像工具处理）。
- 双击缩放、打开/关闭过渡动画（可后补，不影响本设计）。
- 查看器内多图浏览、下载、旋转等图库功能。
- 图片压缩/懒加载/预加载逻辑的任何改动。

## Decisions

### D1: 角标 = 门票（门控字段），而非全图开放

场景字段 `imageZoom: true` 同时控制角标显示与点击响应；未标记图片点击无反应。

- **为什么不全图开放**：全图可点会让玩家逐图找彩蛋，多数是空找，稀释角标"这里值得看"的信号价值；门控契约会干净——有 🔍 就能点，没有就不能点，与项目"显式声明"的数据驱动惯例一致。
- **代价（已接受）**：玩家点未标记图片无反应可能困惑；手机端未标记的缩小图无法救。判定依据：非地图/纸张类图片玩家本来也不会尝试点击。
- **备选方案**：全图开放 + 角标仅作"值得看"提示（探索阶段方案 A），被作者否决。

### D2: 查看器覆盖层，而非容器内滚动

图片区容器保持现有尺寸与布局，查看器作为独立 fixed 覆盖层实现。

- **为什么不选就地滚动**：容器内滚动会改变 `#image-area` 的溢出模型，桌面文本卡 -200px 叠压、手机 `min(56.25vw, 42dvh)` 丧尸遮罩对齐公式都要跟着改；查看器不动任何现有布局，风险面最小。
- **附带收益**：丧尸遮罩/雨滴/暗角全部无需适配查看器——查看器 z-140 天然盖在它们上面。

### D3: z-index 140，QTE 条（150）浮在查看器之上

倒计时不暂停，但 QTE 条始终可见。

- **为什么不暂停**：暂停/恢复需要给 QTE 引入新的时序状态机，且"看图暂停末日"违背难度哲学（死亡是黑色幽默卖点）。条在、时间在烧，玩家是自主选择冒险看图。
- **层级取 140**：高于文本展开（101）与状态栏（120），低于 QTE 条（150）；存档弹窗（10000）与预加载（9999）不受影响。
- **CLAUDE.md 层叠顺序表需同步加一行。**

### D4: 记忆闪色启动时自动关闭查看器

`applyMemoryFlash` 开头调用 `closeImageViewer()`。

- **为什么不共存**：闪色播在特效层（z-50），会被 z-140 的查看器整个盖住，玩家错过序列等于必死——这是意外不公平，不是作者设计的陷阱。自动关闭是一行调用，语义也通顺："有东西吸引了你的注意"。

### D5: Pointer Events 统一桌面与触屏手势

缩放/平移用 Pointer Events（`pointerdown/move/up` + 双指针跟踪）实现，不分别写 mouse/touch 两套。

- 现代浏览器（含 iOS Safari 13+）全支持；查看器元素 `touch-action: none` 接管手势，与手机端图片区的 `user-select: none`/`-webkit-touch-callout: none` 互不干扰。
- 单击 vs 拖拽以位移阈值（~5px）区分：超阈值取消关闭语义。
- 滚轮缩放以光标位置为中心（保持光标下图 content 不动点的标准做法）；缩放上界 4×、下界 contain-fit，用 CSS `transform: translate() scale()` 实现，不引入 canvas。

### D6: 查看器 DOM 静态声明在 index.html，引擎按需显隐

新增 `#image-viewer`（背板 + `<img>` + 🔍 角标元素 `#zoom-badge` 挂图片区），与引擎顶部 `getElementById` 集中取元素的既有风格一致；不动态创建 DOM。

- 查看器图片复用当前 `sceneImage.src`（已被预加载/浏览器缓存，打开即时）。
- **角标归属**：`#zoom-badge` 放在 `#image-area` 内，`renderScene` 按当前场景的 `imageZoom` 字段切换显隐（同 `showRain` 每场景重置惯例）。桌面端位置避开右上角状态栏，定在右下角并抬到文本卡 -200px 叠压区之上；手机端在媒体查询内改为贴图片区右下角。

### D7: 关闭钩子挂在 renderScene 主路径

`renderScene` 开头无条件 `closeImageViewer()`——选项跳转、QTE 超时、回溯、重启、全局触发器跳转全部收束于 `renderScene`（存档模块的"单一 hook 点"结论同样成立），一处调用覆盖所有场景切换路径。Esc 监听只在查看器打开时激活。

### D8: 纯 UI 态，不进 gameState/存档

查看器开关、缩放、平移全部存引擎局部变量；读档恢复后必然关闭。

- **无 SAVE_VERSION 升级**：`gameState` 结构不变，老存档完全兼容。

### D9: 桌面 cursor 只在标记场景生效

`cursor: zoom-in` 通过引擎在标记场景给 `#image-area` 加 class 实现，样式写进 `@media (hover: hover)`（符合项目 hover 规范）；未标记场景与触屏设备无变化。

## Risks / Trade-offs

- [桌面文本卡盖住图片底部 200px，该区域点击走的是文本逻辑] → 可点图片区域仍足够大，不处理；角标位置抬到叠压区之上作视觉引导。
- [查看器打开期间打字机/分段文本继续在背后播放] → 可接受：关闭后文本已播完，选项照常出现；与"读档后 QTE 从满时长重开"同属体验向取舍。
- [玩家在有 QTE 的场景沉迷看图被超时判死] → 有意设计：QTE 条浮在查看器上始终可见，属玩家自主选择，符合难度哲学。
- [触屏捏合与浏览器自身缩放手势冲突] → 查看器 `touch-action: none` + `overscroll-behavior: contain`；页面 viewport 允许缩放的既有决定不受影响（查看器全屏时系统手势只作用于背板）。
- [角标 🔍 为 emoji，不同平台渲染差异] → 可接受（项目状态栏按钮已用 emoji 风格）；若观感不佳，实现时改为 CSS 绘制的放大镜图标，不影响本设计。

## Migration Plan

纯增量变更，无数据迁移：

1. 引擎 + 样式落地后，未标记场景行为与现状逐像素一致（回归基线：随便点现有场景图无任何反应）。
2. 初始卧室挂标记 + 教学文案，新玩家首局即可学。
3. 三张文档特写场景（利昂的工牌、库房的手机、高锦睿给的地图）挂标记。
4. 回滚 = 还原四个文件的提交即可，无存档兼容负担。

## Open Questions

- 角标的具体视觉（emoji 🔍 还是 CSS 图标、大小、透明度、是否带"点击放大"文字）——实现时对照真机截图定，不影响规格与任务拆分。
- 双击缩放与打开过渡动画——作为后续增强候选，本变更不做。
