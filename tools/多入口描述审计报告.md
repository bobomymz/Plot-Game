# 多入口描述审计报告

> 「可多次/从多个节点进入的节点，却只有第一次进入的描述」
> 生成日期 2026-09-29　工具 `tools/entry_desc_audit.mjs`　明细见 `tools/entry-desc-report*.md`

## 结论

全图 **1470 个场景**里，机器筛出 **167 个候选节点**（P0 39 / P1 103 / P2 25）。

在仁济、张江、建平、新达汇四个区域抽出 **12 条逐行读源码核实**，**12 条全部成立**。其中最严重的一类是**一次性事件被重播**（"压差崩了"每回合重演一次），最普遍的一类是**房间→子物体→回房间，房间又把"推门走进"播一遍**。

按已核实的样例密度推算，全图 P0（39 个）里大概率有 25~35 个是真错。修文中主干区域（新达汇 34 个候选、建平 19 个）问题最集中，仁济/金谊因为已经大量写 `_lastScene` 承接，反而是全项目最干净的参照样板。

## 一、方法

`node tools/entry_desc_audit.mjs [区域] [--min=2]`

1. 按 `index.html` 顺序加载全部 `story/*.js`，用**五种状态变体**（初始/全真/全假/夜晚/全访问）调用函数型 `choices`，求跳转边的并集 → 正图 + **反图**（每个节点的所有来源）。
2. 对入度 ≥2 的节点，把**每一个来源**分别代入 `vars._lastScene` 求一次 `text`，抽首句。
3. 判定"这个入口有没有被文案差异化"：把目标场景源码里的 `nextScene/elseScene/timeoutScene` 行**剔除后**，搜来源名字符串。差异化写法必然形如 `vars._lastScene === "来源"`，搜不到 = 这个入口**一定**落进默认分支。
4. 剩下的「未呼应入口」若落在含入口动词/到达/方位/首次限定词的句子上，列为候选。

**定级**
- **P0**：存在子节点回环/自环却仍播进门句 —— 房间 A → 子动作 → 回 A，A 又播一次进 A 的描述。
- **P1**：≥2 个未覆盖来源共用同一句到达描述（场景互跳型）。
- **P2**：单个未覆盖来源落在含到达/方位描述的分句上。

**工具的三条局限（已确证）**
1. 变体穷举不到极端状态组合 → **入度是下界**，不会高估。
2. 工具把「来源」和「状态」解耦，个别组合在实机不可达（例：`建平-宿舍-内部` 只有清场后才出现休息选项，工具却用未清场状态去求首句）。**每条候选都需人眼确认一次状态可达性**。
3. `coveredBy` 判定必须在**剔除跳转行之后**搜索 —— 第一版用原始源码搜，`nextScene:"子场景"` 里的来源名会让大量未差异化节点被误判为"已覆盖"，候选数从 190 虚降到 109。修正后回到 167。

## 三、四类形态（按严重度排序）

### ① 一次性事件重播（最严重）
循环的 QTE/回合节点，每轮返回都把"事件发生的那一瞬间"再演一遍。

```js
// story/张江.js:1434  张江-华大-风淋舱-泄漏
text: function(vars) {
  var desc = "你刚把外门拉开一条缝，舱内“轰”的一声——压差崩了。\n一股看不见的东西从洁净区那侧的缝隙里反灌进来……";
```
「乱拍面板」「拍门喊救命」两个选项都跳回本节点 → **每一轮都重新"崩"一次**，还附赠"就是一时间"的错位感（"你刚把"）。同型：`张江-加油站`（每轮"你走到加油站跟前"）。

### ② 子节点回环（最普遍，也最好修）
房间 → 查看某物 → 返回房间，房间把进门句再播一遍。

```js
// story/东明街道/新达汇.js:3838  新达汇-1F后勤仓库
text: function(vars) {
  var desc = "你推开门。这是一间小型储物仓库，货架上堆着一些落满灰的清洁用品。\n靠墙码着两箱矿泉水……";
```
「拿水/换水/已开封瓶/撕不开」四个子场景的收尾都跳回这里 → 玩家拿完水，画面又"你推开门"。

### ③ 漏配来源（多场景互跳）
写了 `_lastScene` 差异化，但**漏了几个来源**，这些来源落回默认句，默认句恰好是"从外面进来"的写法。

```js
// story/仁济南院.js:48  仁济南院-浦锦路
var fromHospital = ["仁济南院-门诊大门", "仁济南院-救护车通道", "仁济南院-地下停车场"].indexOf(vars._lastScene) >= 0;
": "你下了高架，沿着一条两侧种满香樟的路前进。……"
```
实际来源有 5 个，**漏了「仁济南院-地下停车场-惊动丧尸群」** —— 从地下车库逃命窜到浦锦路，画面却说"你下了高架"。这是四类里最隐蔽的一类：只差一个字符串。

### ④ 修错位置（比不修更糟）
```js
// story/东明街道/新达汇.js:633  新达汇-1F味千拉面
var desc = "你钻进卷帘门，来到味千拉面店内。\n灶台上的汤锅已经冷透了……";
if (vars._ramenVisited) desc += "\n你之前已经来过这里，卷帘门还维持着你离开时的样子。";
```
作者意识到了重复进入，但只在末尾**追加**了提示，首句没动。结果从「小饼干/没吃的/徒手」三个子节点返回时，画面是：

> 你钻进卷帘门，来到味千拉面店内。……你之前已经来过这里，卷帘门还维持着你离开时的样子。

从前台抽屉回来却"钻进卷帘门"，比不修更自相矛盾。**重复提示必须换掉首句，不能追加。**

### 附：相对性表述（中间操作 / 方位词）
用户特别点名的这一类，机器只能标tag，给不出判定，清单里已标 `方位`。典型：`张江-华大-白区` "气密门在身后合拢"（从工位回来没有"身后合拢"这回事）、`建平-校园门口` "你站在建平中学前门马路对面的一棵行道树后，没有急着靠近"（从多个校内节点出来都播这句）。

## 五、修法模板

**金谊广场式（推荐，最省事）** —— 把进门句抽成 `head` 变量，其余环境描述不变：

```js
text: function(vars) {
  var head;
  if (vars._lastScene === "A-子1" || vars._lastScene === "A-子2") head = "你从XX前直起身，退回房间当中。";
  else if (vars._lastScene === "B") head = "你从B那边绕过来。";
  else head = "你推开A的门。";
  return head + "这里是……";   // 环境描述原样不动
}
```

**纯字符串 text 的，就地改函数**（`建平-济美楼-2F` 那种）：直接把 `"你来到济美楼 2 楼。"` 改成 `"济美楼 2 楼。"`，与同文件 3F/4F 对齐是最省事的改法。

**循环型回合节点**（`张江-华大-风淋舱-泄漏`）：用轮次变量分流，第 1 轮播事件，第 2 轮起只播状态。

⚠ 顺序：**先把默认句改成"任何来源都成立的安全句"，再给特殊来源加差异化**。反过来（保留旧默认句、给子场景补一句）在 `_lastScene` 漏配时会立刻打回原形 —— 这就是清单 #7 的教训。
