# 旧存档兼容性修复报告 —— "加新变量后老档报 ReferenceError"

> 2026-09-24 · 触发 bug：`_xinOutcome is not defined`（复旦江湾章节变量）
> 回归工具：`node tools/save_compat_selftest.js`（**27 通过 / 0 失败**）

---

## 一、结论（先看这三行）

1. **不是条件写错、也不是变量没注册。** `core.js:205` 里 `_xinOutcome` 注册得好好的，
   `condition_audit.js` 跑出来两个 0。问题是**玩家的状态里没有这个键**。
2. **根因：存档 / 回溯两条恢复路径不与 `_variables` 对账。** `initGameState()` 的键集来自
   `_variables`，而 `loadSave()` → `applySave()` 是**整块接管旧状态、绕过 `initGameState`**。
   旧档（加新变量之前存的）里没有 `_xinOutcome` → `checkCondition` 的
   `new Function(...Object.keys(gameState))` 里没有这个形参 → `ReferenceError` → 被 catch 吞成
   `false` → 选项静默消失 + 控制台刷报错。
3. **症状只会长在字符串条件上。** 函数式条件写 `vars._xinOutcome` 只会安静地拿到 `undefined`
   （不抛错），所以"全库只有一条报错"是**假象**，不是单点 bug —— 一旦命中这条路径，
   所有引用新变量的字符串条件一起失效。

## 二、证据链

| 检查 | 结果 |
| --- | --- |
| `story/core.js:205` 是否注册 | ✅ 已注册（`_xinOutcome: 0`，同批还有 9 个江湾变量） |
| `node tools/condition_audit.js` | ✅ 0 / 0（源码侧完全干净 → 排除"忘注册"） |
| `checkCondition` 的实现（engine.js:549） | `new Function(...Object.keys(variables), "return Boolean(cond)")`，**变量名 = 状态键名** |
| `initGameState`（engine.js:196） | 从 `_variables` 深拷贝 → **新开局永不出这个错** |
| `applySave`（engine.js:1393） | 原文 `gameState = __wrapState(saved.gameState)` —— **不做任何对账** |
| `backtrack`（engine.js:769） | 原文 `gameState = __wrapState(prev.gameState)` —— 同样不对账，且旧档的 `historyStack` 也一起带进来 |
| 复现代码（测试 §2 对照组） | 删掉 10 个新键 → 同一条件报 `_xinOutcome is not defined` → 返回 `false` ✅ 与原报错逐字一致 |

**第二个洞（同一根因，顺手一起补了）**：`_reactive.computed` 的派生变量（`canSee` /
`hasMeleeWeapon` / `mercuryTier` / `noPainSense` / `hasDimLight` 等 15 个）同样是"引擎算出来的键"，
旧状态里缺了就一样炸。实测：不补时全库 **25 条**字符串条件报错，其中就包含
`zombieAtHomeDoor` / `zombieOutsideHome` / `hasNoTransportation` / `minutesBetweenReduceStrength` 这些派生量。
`hasMeleeWeapon` 等按 CLAUDE.md 的写法本来就**直接写在字符串条件里**，属于在册隐患。

## 三、修复（engine.js，只动恢复路径）

| # | 改动 | 位置 |
| --- | --- | --- |
| 1 | 新增 `fillMissingDefaults(state)`：把 `_variables` 里**新增且状态中不存在**的键填回初始值（只补缺、不覆盖已有值） | `snapshotState` 之后 |
| 2 | `applySave()`：`gameState` 与 **`historyStack` 每一项**都过一遍 `fillMissingDefaults` | 原 1393 |
| 3 | `backtrack()`：`prev.gameState` 过一遍 `fillMissingDefaults` | 原 769 |
| 4 | 抽出 `refreshComputed()`（= `applyReactive` 的第 1 步：只重算派生变量）；`applyReactive` 改为调用它 | 原 604 |
| 5 | `applySave()` / `backtrack()` 在 `_reactiveState` 就位后调用 `refreshComputed()` | 同上 |

**两个刻意的设计选择：**

- **不 bump `SAVE_VERSION`**。bump 的确是最省事的"修法"，代价是**弃掉玩家全部进度**。
  新增变量是纯增量，补初值语义正确，没必要让玩家重开。
  （`手机端适配.md` 的旧约定已加反向条款：只有**改字段含义/结构**才 bump。）
- **恢复路径不调整个 `applyReactive()`**。虽然那样也能把派生量算出来，但它会连规则一起跑，
  把饥饿 / 疲劳结算**提前到读档瞬间** —— 玩家什么都没做就掉体力。抽出的 `refreshComputed()`
  只做第 1 步，规则仍按原流程在第一次 `applyEffect` 时跑，节流记录（`_reactiveState`）照旧。

**游戏行为差异：零。** 派生变量的值与"旧档里原本存的"完全一致（本来就是同一批 `_variables` 派生的），
此次改动只是把**缺失的**键补上。

## 五、还有一件事要你确认（不能从我这边判定）

同一段报错还有**另一种可能**：浏览器缓存了旧的 `story/core.js`（这时 `_variables` 本身就缺键，
本修复补不出来，硬刷新即可）。**控制台跑一行就能分清**：

```js
console.log('_variables 有键:', '_xinOutcome' in storyData._variables,
            '| gameState 有键:', '_xinOutcome' in gameState);
```

- `_variables 有键: true` + `gameState 有键: false` → **本次修的旧档问题**，刷新页面即自动修复。
- `_variables 有键: false` → 缓存问题，`Ctrl+F5` 硬刷新。

**关于你当前那一局的进度**：不用重开。刷新后旧档会被自动补齐，`_xinOutcome` 取 0（= 未入章）；
`_xinOfferDay` 会被 `建平中学.js:765` 在下次到「建平-后门辅路」时自动补记，江湾章节照常可进
（前提是那一刻 `hh < 14`，否则按原规则顺延次日 —— 这条是原设计，不是我改的）。
