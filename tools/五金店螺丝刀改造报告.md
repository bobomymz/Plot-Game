## 三、设计说明

### 3.1 为什么螺丝刀放在"工具区"

工具区文案本来就写着「墙上挂着一排扳手和螺丝刀」——**物件本来就在场景里**，补一个可拾取项比新造场景更自然。
代价是五金店这条路线本身凶险（进去大概率撞上 QTE / 毒气结局），符合"高风险换工具"。

### 3.2 离开选项：把"只进不出"补成"可进可出"

| 节点 | 新增出口 | 去向 |
|---|---|---|
| `五金店-侧窗`（翻窗落地） | 「心里发毛，趁早原路翻出去」 | `五金店` |
| `五金店-侧窗-探索`（工具区） | 「屏住呼吸，原路翻窗退出去」 | `五金店` |

回到门口后 `五金店` text 走新增的 `_lastScene` 分支，写「你从侧窗翻出来，踩着墙根的碎砖落回地面」，不再重播"来到五金店门口"。
原路径（推门 / 躲藏 → 两个死结局）**一字未改**。

### 3.3 三个必须踩准的引擎机制（沿用 401 模式）

1. **`elseScene` 分支不执行选项 `effect`**（`engine.js` `createChoiceButton` 实测）。
   所以背包满 → 走 `整理整理` 时，拾取返回点不能放选项 `effect`，否则失效 → 死链。
   → 做法：**入口场景 `onEnter` 预设** `positionAfterOperation = "五金店-侧窗-拿螺丝刀"`。
2. **入口 onEnter 会因折返重跑**，故必须加 `_lastScene` 守卫，否则从拿取节点回来会重复扣 2 分钟 + 重播追兵出现。
   → `if (vars._lastScene === "五金店-侧窗-拿螺丝刀") return {};`
3. **`_lastScene` 分流的 text**：折返时改用「你把螺丝刀塞进背包侧袋，退回工具区中央。门外那拖沓的脚步声还在……」，
   不再重播「突然听到门外传来声音」。

### 3.4 复用既有变量，不做新物品

螺丝刀沿用 `hasScrewdriver`（布尔）—— 与建平同一件东西：同样占 1 格、同样能在「整理整理」里丢弃、
同样进 `cuttingToolName` 末位（划胶带纸箱可用）。**不需要改存档迁移**（布尔字段，旧档 `false` 默认值即可）。

## 五、遗留项 / 待拍板

1. **【平衡·待拍板】五金店从"纯陷阱房"变成"有诱饵的陷阱房"**：玩家现在可以翻窗 → 拿螺丝刀 → 翻窗走，全程安全。
   若要维持五金店"进来就得付代价"的强度，可考虑给侧窗路线也加一次判定（如离开时触发一次 QTE），或把螺丝刀改到后巷等更险的位置。
2. **【数值·待拍板】** 拾取耗时 1 分钟；首次审视工具区 2 分钟（既有）；翻窗进 3 分钟（既有）。
3. **【既有问题·未改】叙事错位**：侧窗玩家已经在工具区里，点「推开工具区的门看看」却触发
   `结局-五金店-工具区` 的文案「你握住门把手，轻轻推开……一道黑影从门缝上方的货架上直扑下来」——
   这是**从外面进工具区**的描述。属既有 P1（`entry_desc_audit` 已标注该结局节点总入度 2、未做 `_lastScene` 分流），本次未动。
4. **【既有机制限制】** `positionAfterOperation` 是全局变量，玩家离开五金店后该值仍残留为
   「五金店-侧窗-拿螺丝刀」。若之后在别处触发「整理整理」，可能跳回该节点。这是 401 / 安居苑等
   所有用此模式的场景共有的问题，本次未额外处理（项目现状一致）。
