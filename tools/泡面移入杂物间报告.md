# 泡面移入员工通道杂物间 · 改造报告

> 日期：2026-09-28
> 起因：波波反馈「正常进入全家内部可以直接拿到方便面 3 包，有点太富」，要求把 3 包挪进（上一次刚打通探索的）员工通道杂物间。
> 涉及文件：`story/东明街道/全家和公交站.js`、`story/core.js`（仅注释）、`tools/noodle_stack_selftest.js`

## 一、改动前的结构

| 位置 | 内容 |
|---|---|
| `全家便利店内部`（货架） | 文案「促销货架上还码着 N 包泡面」+ 选项「拿一包泡面」→`全家-拿泡面` |
| `全家-拿泡面` | `onEnter` `instantNoodle+=1; itemCount+=1; familyMartNoodleLeft-=1`，出口「继续」→`全家便利店内部` |

即：进店就能连着点 3 次拿满 3 包（每包 1 格、干嚼回满体力），门槛只有背包容量。

## 二、改动后的结构

| 位置 | 变化 |
|---|---|
| `全家便利店内部` | **删**「拿一包泡面」选项；货架文案改为「被翻得乱七八糟，只剩几个被拆开的空纸箱」 |
| `全家-拿泡面` | 文案改为「从墙角纸箱里抽出一包泡面…纸箱里还剩 N 包」；`image` 改`仓库.webp`；出口「继续」→ 杂物间 |
| `杂物间`（`全家便利店-员工通道-丧尸的偷袭-杂物间`） | 正文新增纸箱泡面描述（`familyMartNoodleLeft`）；新增选项「搬走一包泡面」（`showCondition: familyMartNoodleLeft > 0`，容量闸门 `itemCount < bagVolume`，满则 `elseScene: 整理整理`） |
| `全家便利店-员工通道`（安全走廊） | **新增**「翻看那间杂物间」入口 → 杂物间（门控：没翻过、或泡面没拿完） |
| QTE 仓库的杂物间热点 | 门控由「没翻过」放宽为「没翻过 或 泡面没拿完」，拿完且翻过才消失 |
| `core.js` | `instantNoodle` / `familyMartNoodleLeft` 注释由「促销货架」→「员工通道杂物间」 |

数值完全未动：仍是 **3 包**、**每包占 1 格**、**`instantNoodle` 0~3**、**吃 = 体力回满**、**丢弃 = 损失不回补**。

## 三、为什么必须同时给安全走廊加入口（可达性）

改动前，杂物间**只有一条路能进**：`全家便利店内部 → 打手电筒探索员工通道`，且必须**有丧尸**（进 QTE 仓库），打赢后**当场**翻找。问题：

1. 走「饼干引路」安全线的玩家进的是 `全家便利店-员工通道`，那里**没有**杂物间入口 → 永远拿不到泡面。
2. 打赢 QTE 后一旦退出仓库，`FamilymartHasZombie=false`，再进员工通道走的是**安全走廊**（`condition: _visit['零食引路'] || !FamilymartHasZombie`），同样进不去。

故给安全走廊补同款入口，使两条手电筒线都能到杂物间（共用同一场景）。**摸黑线仍不给**——对齐既有设计（无手电时摸黑只找到旧工作服，正文原话「也许下次带个手电筒来会有收获」），也与钥匙的获取口径一致。

## 四、本次顺带修掉的两个坑

1. **安全走廊 onEnter 重复计时**（我这次改动新引入的风险，当场堵上）
   `全家便利店-员工通道` 的 `onEnter` 有 `updateTime(3)`（进走廊耗时）。新增「走廊 ↔ 杂物间」往返后，从杂物间折返回走廊会**再扣一次 3 分钟**（项目老坑：非休息入口退回自身场景 → onEnter 重跑）。已加精确守卫：
   ```js
   if (vars._lastScene === "全家便利店-员工通道-丧尸的偷袭-杂物间") return {};   // 折返不再重复计
   ```

2. **既存 lint E：图片路径写错**（非本次引入）
   `全家便利店-员工通道` 的 image 返回 `images/全家和公交站/仓库-清场.webp` —— **漏了 `小区周边/`**，该目录从未在 git 中存在过。已修正为 `images/小区周边/全家和公交站/仓库-清场.webp`。旧基线 lint 报告里这条 E 就已在册（连同建平化学实验室 3 条）。

3. **`noodle_stack_selftest.js` 里一条过时断言**（非本次引入）
   S3 引用的出口文本 `'不丢，谢谢'` 在 `core.js` 里早已不存在（现出口为 `×`，`showCondition: itemCount <= bagVolume`）。因 S1 早先就会崩，S3 从未跑到，断言腐烂至今。已修正。
