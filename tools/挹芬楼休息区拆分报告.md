# 建平-挹芬楼-1F-休息区 · 休息动作拆分报告

- 日期：2026-09-29
- 改动源码：`story/建平中学.js`、`tools/convert-images.py`
- 新增资源：`images/建平/挹芬楼-1F休息区-没人{,-evening,-night,-雨}.webp`

## 一、目标

把「建平-挹芬楼-1F-休息区」里的**休息机制**（体力恢复 + 就地整理入口）拆到独立子节点，
原节点退回为纯粹的「到达 / 观察 / 枢纽」场景。

## 二、结构（拆分前 → 拆分后）

拆分前：一个节点既管"到达"又管"休息"

```
建平-挹芬楼-1F-休息区
  image   : 弹琴图（分雨/阴/默认）
  onEnter : restTidyGuard + restRecover(1) + currentPos + _travelMinutes=0
  text    : "你在长椅上坐下…"（休息动作）+ restHint
  choices : 去饮料机 / 🎒整理 / 回东侧走廊
```

拆分后：

```
建平-挹芬楼-1F-休息区                 ← 观察枢纽（保留原 ID）
  image   : restAreaImage
  onEnter : currentPos + _travelMinutes=0（不再含 restRecover / guard）
  text    : 按 _lastScene 三分流
            ←休息区-休息 : "你从长椅上站起来，走回休息区中间。…"
            ←饮料机     : "你从饮料机那边绕回来，重新站到休息区中间。"
            其它(首进)  : "你走进休息区。几张长桌拼在中间，靠墙一排藤椅…"
            + 彭奕宸在弹琴时追加琴声段（原文保留）
  choices : 去饮料机 / ★在长椅上坐下歇会儿 → 新节点 / 回东侧走廊

建平-挹芬楼-1F-休息区-休息            ← 休息机制载体（新增）
  image   : restAreaImage（与观察节点同源，保证同一时刻画面一致）
  onEnter : restTidyGuard + _travelMinutes=0 + restRecover(1)
  text    : _visit>1 分流（"你又坐回长椅上…" / "你在长椅上坐下…"）+ 弹琴余韵 + restHint
  choices : 继续歇一会儿(自环) / 🎒整理(restTidyChoice 指向本节点) / 起身 → 观察节点
```

## 三、关键设计点

1. **新节点 ID 以「休息」结尾** → 命中 `story/建平中学.js` 尾部 Harsh 包装器的 `NON_PLACE` 正则
   （该表按 ID 后缀匹配）→ 不记轨迹、不追加距离提示、不做校园打铃。
   这正是子节点应有的行为，源码注释原本就写明「"休息区"安全，"休息"不安全」。
2. **整理入口随休息机制一起搬走**：`restTidyChoice("建平-挹芬楼-1F-休息区-休息")`，`restTidyGuard` 置于
   新节点 `onEnter` 首行。原节点删除了 guard 与整理入口（整理属休息场景功能）。
3. **多入口描述**：原节点 3 个入度（东侧走廊 / 饮料机 / 休息节点"起身"）用 `_lastScene` 分流；
   新节点用 `_visit[...] > 1` 分流"继续休息"（与其自环一致，避免重复播首进句）。
4. **抽出 `restAreaImage(vars)`** 供两节点共用：彭奕宸在弹琴 → 弹琴图（白天分雨/阴）；否则 → 空景图（分时段 + 雨）。
   同时修正了原逻辑的瑕疵：旧版**无论彭奕宸在不在**都显示弹琴图，现在非弹琴时段正确显示空景。
5. 原节点保留 `_travelMinutes = 0`（"到达休息区即结束这段行程"），新节点同样清零——与全图休息节点惯例一致。

## 五、工具增强（`tools/convert-images.py`）

新增两个可选参数，**无参数调用行为不变（全量）**：

- `--only <路径...>`：只转指定文件（相对项目根，支持 `*` 通配）。
- `--keep`：保留原图不删。

起因：全量转按「去后缀同名」生成 webp，会**静默覆盖**已存在的同名 webp。
本例中 `…-彭奕宸弹琴.jpg` 会把正式图 `…-彭奕宸弹琴.webp` 覆盖掉——只补几张新图时这是误伤。
同时修掉自己引入的坑：`--only` 模式下 `tools/image-map.json` 原本会被增量结果冲成 1 条，
现改为**合并写回**（本次 4 条 + 原有 1 条 = 累计 5 条）。
