## 二、判定函数（`story/utils.js`）

| 函数 | 行 | 作用 | 优先级 |
|---|---|---|---|
| `hasMeleeWeapon(vars)` | 331 | 是否有近战武器（6 个 flag 或） | — |
| `meleeWeaponName(vars)` | 337 | 返回**最优**近战武器名，无则 `""` | 斧头 > 匕首 > 铁管 > 拐杖 > 拖把杆 > 美工刀 |
| `heavyWeaponName(vars)` | 349 | 适合砸锁/撬门/拨藤蔓的重武器名 | 斧头 > 铁管 > 拐杖 > 拖把杆（刀类不算） |
| `meleeWeaponTier(vars)` | 359 | 档位 0–3：空手0 / 美工刀·拖把杆1 / 铁管·拐杖2 / 匕首·斧头3 | — |
| `cuttingToolName(vars)` | 735 | 割/锯类（划开胶带纸箱） | 美工刀 > 匕首 > 斧头 > 螺丝刀 |

**`_reactive.computed` 注册**（core.js:367-368）：`hasMeleeWeapon`、`meleeWeaponTier`
→ 因此字符串条件可直接写 `hasMeleeWeapon`、`meleeWeaponTier >= 2`，无需函数条件。

调用量（全 story/）：`hasMeleeWeapon` 47、`meleeWeaponTier` 14。

## 三、耐久机制（方案 C：损坏即降档，无连续耐久条）

没有任何"耐久点数"，武器只有**断 / 不断**两态。断了 → `hasXxx=false` + `itemCount-1` → 上面的 `meleeWeaponName`/`meleeWeaponTier` 自动降档、次优武器补位、拾取点的 `!hasXxx` 守卫重新开放（断了回原处再淘一把是**预期行为**）。

| 成员 | 行 | 说明 |
|---|---|---|
| `WEAPON_FLAG` | 371 | 武器名 → flag 映射 |
| `COMBAT_BREAK_CHANCE` | 372 | 战斗失败损坏概率：**弱1 = 0.5 / 中2 = 0.25 / 强3 = 0.1** |
| `HEAVY_USE_VAR` / `HEAVY_USE_LIMIT` | 373-374 | 撬砸寿命：铁管 3、拐杖 3、拖把杆 1；斧头无限不计 |
| `breakWeaponByName(vars, name)` | 377 | **唯一损坏入口**：置 false、`itemCount-1`、清重活计数、写 `_weaponJustBroke` |
| `tryBreakWeapon(vars)` | 389 | 战斗失败/超时节点 `onEnter` 调用，**只挂失败**，成功不耗 |
| `countHeavyUse(vars, name)` | 400 | 选项已点名具体武器时手动计数（如上实南校天桥"用铁管撬开"） |
| `useHeavyTool(vars)` | 411 | 撬砸类动作节点 `onEnter` 调用，自动取 `heavyWeaponName` 并写 `_pryTool` |
| `weaponBrokeText(vars)` | 420 | 一次性报废旁白，读 `_weaponJustBroke` 后清除（**53 处**） |

`tryBreakWeapon` 挂点 **30 处**，`useHeavyTool` 8 处，`countHeavyUse` 10 处。

**文本回读陷阱**：武器断后 `heavyWeaponName` 会指向次优武器，所以撬砸场景文案必须读 `vars._pryTool`（core.js:268 注释）。

## 四、战斗体力消耗（成功也累）

| 成员 | 行 | 说明 |
|---|---|---|
| `combatCost(vars)` | 434 | `meleeWeaponTier >= 2 ? 1 : 2` → 空手/弱武器 **−2**，中/强武器 **−1** |
| `combatDrain(vars)` | 441 | 胜利节点 `onEnter`，直接改 `vars.strength`，扣值写 `_lastCombatDrain` |
| `combatDrainText(vars)` | 452 | 一次性橙色【系统提示】，读后清除（**35 处**） |

适用范围（utils.js:428-431 注释）：**QTE 缠斗型战斗的胜利节点**。
不挂：选择式速杀/剧情杀、非挥武器特殊战（关阀/抵门/躲闪沟通）、失败节点、开枪（耗弹不耗体力）。

`combatDrain` 挂点 **31 处**。扣到 0 会触发全局"体力耗尽猝死"——打赢了却累瘫是预期的黑色幽默。

## 五、枪械机制

- 弹药只在警察局首次取枪时给 3 发（`_policeGunTaken` 一次性）。
- 统一扣弹写法：`v._lastShotFired = v.gunAmmo > 0; if (v._lastShotFired) v.gunAmmo = Math.max(0, v.gunAmmo - 1);`
  → `_lastShotFired` 让 `nextScene` 能区分"打空最后一发"与"空枪"（避免最后一发被判成空枪）。
- 开枪常带 `{ add: { chasedByZombies: 2 } }`（枪声引尸），比近战 +1 更重。
- 硬门槛示例（张江桥）：`hasGasMask && maskRemainingUses > 0 && hasGun && gunAmmo >= 3`。
- 丢弃手枪会同时清 `gunAmmo: 0`（core.js:760），重取枪不再补弹。

## 六、背包 / 丢弃交互

- 武器占 `itemCount` 一格，拾取四件套：`condition:"itemCount<bagVolume"` + `effect:{set,add:{itemCount:1}}` + `elseScene:"整理整理"` + 新节点 `set positionAfterOperation`。
- 丢弃菜单（core.js 658-768）：铁管 / 拐杖 / 拖把杆 / 美工刀 / 斧头 / 手枪 / 匕首 全部可丢，丢枪连弹药清 0。
- **`breakWeaponByName` 内部会 `itemCount-1`**，所以武器损坏会**自动腾出一格**。

## 八、一致性观察（未改动，供拍板）

1. **拐杖 / 拖把杆拾取点缺 `!hasXxx` 守卫**（安盛街:236、安盛街:551）——只有背包闸门，没有"已持有"闸门。目前靠"该场景是一次性流程节点"兜底；若未来让这两处可重入，会出现重复 +1 格。斧头/匕首/枪/美工刀的拾取点都有 `!hasXxx` 守卫。
2. **斧头有三个获取点**（警察局 / 新达汇 B1 / 建平车库），各自都有 `!hasAxe` 守卫，不会重复计数；但斧头撬砸无限寿命 + tier3 战损仅 10%，实际是最优解，三选一即可拿满。
3. **`hasIronPipe` 声明注释仍写"打斗中才能获得"**（core.js:107），实现上就是打完 `拳打脚踢2` 拾取，注释与实现一致但措辞偏旧，可考虑改清楚。
4. **重工具寿命表不含斧头**：`HEAVY_USE_VAR` 只有铁管/拐杖/拖把杆，`useHeavyTool` 取到斧头时 `countHeavyUse` 直接返回不计数——即斧头撬砸无限次，是设计（"斧头无限不计"），不是漏配。
5. **开枪完全绕过耐久与体力体系**：不耗体力、不损坏、不进 `meleeWeaponTier`。唯一代价是弹药 + `chasedByZombies +2`。
