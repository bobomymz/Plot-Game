# 记忆闪色战斗 · 三档判定改造报告

> 日期：2026-09-29　改造范围：全库 47 场闪色战斗　作者拍板：波波
> 工具：`node tools/flash_battle_audit.js`（迁移清单/终检）、`node tools/flash_battle_selftest.js`（判定专项自测）

## 一、结论

原机制是**全等比对**：答案差一个计数即走 `elseScene`（多为死亡结局），超时同死。改为**距离计分 + 分档**：

| 偏差 | 判定 | 说明 |
| --- | --- | --- |
| **0** | **胜利** | 各色计数完全一致（顺序无关） |
| **1 ~ 2** | **受伤** | 记岔 1~2 个计数，仍能脱身 |
| **≥3 或超时** | **死亡** | 记岔太多 / 没作答 |

**偏差 = Σ|玩家报数 − 实际数|**（跨全部颜色；报不存在的颜色按所报数量计）。这是**绝对偏差**、不是百分比——好处是与序列长度无关，len 4~10 全适用，不用逐场调门槛。
反刷分：多报不加分（多报 5 个不存在的绿 = 5 偏差）；乱填满色 50 偏差、空输入 = 总闪色数，**都必死**，与旧行为一致。

## 三、惩罚设计（utils.js）

| 函数 | 作用 |
| --- | --- |
| `flashAnswerDeviation(vars)` | 读 `_input` / `_currentAnswer` 算偏差 |
| `flashCombatRouter(胜,伤,死)` | 三档路由（挂 `nextScene`） |
| `flashCombatRouterSafe(成功,非致死)` | 两档路由 |
| `hurtPenaltyBase(vars)` | 公共受伤包：**汞 +5×偏差**（封顶 100）、`hurtByZombie`、`tryBreakWeapon` |
| `hurtWinOnEnter(opts)` | 受伤-干死：体力 `-(combatCost+1)`、`_lastCombatDrain`；`{human:true}` 对手是人（路霸）→ 不挂尸伤/汞；`{pos,time}` 可选 |
| `hurtFleeOnEnter(opts)` | 受伤-跑路：体力 -2、追兵 +`chase`（默认 1，可传 0）、`hurtPenaltyBase` |
| `hurtCostText(vars, withWound)` | 一次性代价提示（体力行 + 抓伤行；`withWound=false` 给人类对手） |

- **超时**：三档场景 `timeoutScene` 一律**维持死亡**（没作答 ≠ 答错，不吃受伤保底）。
- **汞不出现**在玩家可见文案里（禁止点破机制），只走 `hurtCostText` 的"被丧尸抓伤"描写。
- 两个路由函数挂 `__sceneRefs` 属性，供 `lint_story.mjs` 补记入边（见第五节）。

## 四、沿用的既有模式

- 受伤场景一律做成**独立场景**（自带收尾 + 复刻胜利场景的出口），不做成胜利场景的子节点——与 `张江.js` / `建平中学.js` / `仁济南院.js` 已落地的写法一致。
- 每个 `flashCombatRouter` 的三个目标（含受伤场景）都已 `scene_fn_selftest` 校验存在。
- `_visit` 门控：受伤档视同"已制服/已清场"的可复现状态（如 仁济-检验科/住院部/太平间的 `_xxxCleared` 旗标、新达汇 3F 灭火器已喷完），与胜利档口径一致。

## 五、连带修复（工具层）

1. **`lint_story.mjs` 入边盲区**：路由的目标 ID 是以**字符串实参**传给工厂的，运行时闭包源码里只有变量名 → lint 扫描不到 → 全部受伤场景被误报「无任何入边（孤立场景）」（曾一次刷出 29 条假 W）。修法：路由返回的闭包挂 `__sceneRefs`，lint 的 `harvestLiterals` 显式读取。**效果：W 129 → 100，受伤场景孤立误报清零。**
2. **`xin_chapter_check.js`**：闪色题改为路由后，walk 在 `_input` 为空时偏差=满值 → 误走死亡档，导致「学生救场全歼」2 条断言失败。修法：walk 遇到 `choice.input` 时先填完美答案（`_input = _currentAnswer`）。**74 通过 / 0 失败。**
3. **`flash_battle_audit.js`**：改为「运行时 + 源码扫描」双通道——只用运行时 `choices()` 会漏掉**闪色选项被状态门控**的场次（如 全家-摸黑 仅在 `FamilymartHasZombie` 为真时才 push 闪色选项）。

## 七、遗留 / 待你拍板

1. **5 场两档场景沿用原有固定惩罚**（汞 +10 / 体力 -2 等），**未改为按偏差比例**（1~2 偏差都是同一档）。若要和新受伤档统一成"汞 +5×偏差"，说一声即可批量改。
2. **益丰-沟通被咬 的 timeout 由"死亡"改为"被咬到了"**（跟随"这 5 场不致死"的口径统一）。原设计是超时死、答错不死，二者不一致——按你的选择统一成非致死。若要恢复"超时仍死"，说一声。
3. **正门硬闯 / 群架 / 杀出去 等"跑路档"的追兵数**：正门硬闯场景 `onEnter` 已自带 `chasedByZombies+1`，故跑路档传 `chase:0` 避免叠加；其余跑路档 `chase:1`。若你认为跑路该更狠（+2），可逐场调。
4. **益丰-打群架** 的选项 `effect` 里有 `_lastCombatDrain:1`（供十字路口事后提示），跑路档的 `hurtCostText` 会先读走它 → 十字路口那次 `-1` 提示在受伤路径上不再显示（体力实扣不受影响）。属提示粒度问题，未动。
