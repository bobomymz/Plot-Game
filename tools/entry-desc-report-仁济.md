# 多入口进入描述审计 · 仁济

- 生成：`node tools/entry_desc_audit.mjs 仁济 --min=2`
- 方法：五状态变体求跳转并集 → 反图 → 把**每个来源**代入 `vars._lastScene` 求一次 text 首句 → 剔除目标场景源码里出现过的来源名（已差异化）→ 剩下的「未呼应入口」若落在含入口/到达/方位词的句子上，列为候选
- ⚠这是**候选生成器**，不是判定器。每条都要人眼收口：与来源无关的通用描述（如“你环顾四周”）对任何入口都成立，属正常。

## 按文件统计

| 文件 | 场景数 | 候选 | P0 | P1 | P2 |
|---|---|---|---|---|---|
- **P0**：存在「子节点返回/自环」却仍播进门句 —— 房间 A → 子动作 → 回 A，A 又播一次进 A 的描述。几乎必错。
- **P2**：单个未覆盖来源落在含到达/方位描述的分句上，需人眼确认是否真的违和。
