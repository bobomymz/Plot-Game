## 0. 结论先行

1. **能做，而且现有引擎已经支持**：`engine.js:86` 用 `innerHTML` 渲染正文，打字机遇到 `<` 会整段一次性插入标签（`engine.js:68-79`），日记本已经在用 `<br>`。零引擎改动就能上手。
2. **建议走「语义 class」而不是继续写 inline style**：现状是 **265 处** `<span style='color: ...'>` 硬编码散在各文件里，改一次配色要动 265 处。方案是 `style.css` 里定义 ~20 个语义 class，剧情里只写 `<span class='crit'>`。
3. **最大的风险不是技术，是「用力过猛」**：1470 个场景、8.5 万字正文，如果逐词着色会变成圣诞树，反而没人看了。方案给出**配额制**（每段最多 2 处强调、环境色只做整句不做单词）和**分阶段上线**，每阶段能独立验收、能回滚。

## 2. 技术硬约束（决定「什么能做什么不能做」）

| # | 约束 | 后果 |
|---|---|---|
| C1 | `#scene-text` 是 `<p>`（index.html:31） | **只能用行内元素**：`span / b / i / em / strong / small / mark / code / q / ruby / sub / sup / br`。写 `<div>/<p>/<ul>/<table>` 会被浏览器自动闭合 `<p>`，后面的文字跑到段外、样式全丢。<br>→ 「引文块」「短信气泡」这类块级排版**做不了**，只能用行内样式（底色/字体/字距）模拟。 |
| C2 | 打字机每 tick 执行 `element.innerHTML = result`（engine.js:86） | 打字过程中 DOM 每帧重建 → **CSS `animation` 会不停重启**。入场动画（抖动/闪烁）在打字时是「抽搐」，打完后才完整播一次。短动画可接受；长动画不行。若要优雅，需要引擎小改：打字完成后再给元素挂动画 class（可选，见 §6 待拍板）。 |
| C3 | 选项按钮用 `textContent` 渲染（engine.js:820/910/969） | **选项文本目前不支持 HTML**，写进去会原样显示标签。想让选项也上色必须改引擎（`innerHTML` + 白名单过滤）。 |
| C4 | `{变量名}` 插值在标签内部照常生效 | `<span class='sys'>【系统提示】体力+1，当前体力：{strength}。</span>` 正常。但**标签属性里不要写 `{}`**。 |
| C5 | 文本不做 HTML 转义 | 正文里出现裸 `<` `&` 会被当标签吞掉。现状干净（已检查），但今后写文要避开；日记本玩家手写内容已转义，保持。 |
| C6 | `tools/lint_story.mjs:182` 已 `stripHtml()` 后再查规范 | 加标签**不会**触发 lint 误报（空行/直角引号/插值变量检查都走去标签后的文本）。<br>⚠ 但 `tools/ai_phrase_scan*.py` 只归一化 `{var}`、**没有去标签** → 加标签后「AI 雷同表述」会被标签打断而漏检，需给扫描脚本补 `stripHtml`（§6）。 |
| C7 | 分段停留时长按去标签字数计算（engine.js:139） | 加标签不影响阅读节奏，安全。 |

**使用配额（防止过花，写进规范）**
- 单段（一个 `\n` 分隔的自然段）最多 **2 处** 强调类（`crit/sfx/shout`），**1 处** 环境类。
- 环境色包**整句或分句**（4–25 字），不包单词；一句话里如果主体不是环境，不上色。
- 同一 class 不在相邻两句连用。

## 6. 需要新增/改动的配套工具

1. **`tools/text_markup_lint.js`（新）**：全量扫描剧情文本里的标签，报
   - 非白名单 class（拼错即报）
   - 标签未闭合 / 嵌套错乱
   - **出现 `<div> <p> <ul> <li> <table> <h1>` 等块级标签（会撑破 `<p>`）— 直接 E 级**
   - `{变量}` 写在标签属性里
   - 裸 `<` / `&`（非标签但会被吞）
2. **`tools/text_markup_scan.js`（已建）**：候选清单生成器，改造过程中反复重跑看剩余量。
3. **`tools/ai_phrase_scan*.py`（小改）**：加 `stripHtml`，否则加标签后雷同表述检测会漏检。
4. **`tools/text_style_preview.html`（新，可选）**：把本文 §4 的所有样例用新样式渲染出来，浏览器打开即可对照配色。

## 7. 待你拍板的 6 件事

1. **是否给「可拾取物品」上色**（如 `num`/`gain` 高亮）？—— 会显著降低探索难度，属于平衡改动，**我不默认做**。
2. **选项文本是否也支持 HTML**？需要改 `engine.js` 三处 `textContent → innerHTML` + 白名单过滤。好处：选项里的「赌一把」「回头」能上危险色；代价：引擎改动 + 玩家手写内容注入面变大。
3. **`sfx` 放大到多少**？建议 1.35em。手机上 `line-height:1.9` 下，1.4em 以上会有行高跳动，建议上限 1.4em，需真机确认。
4. **气味分档是否要做成三种颜色**？信息量更大，但也可能让玩家觉得「颜色在教我闻」。备选：气味统一一色，只在化工毒气（危险）时用警示色。
5. **汞中毒视觉重影（`chem` / `numb`）是否上**？表现力强，但等于给了玩家一条非文字线索。项目规则是「玩家可见文案禁止点明机制」，视觉暗示算不算点明，你定。
6. **现有 `#00fbffff` 青是否换成柔和的 `#4ec9d4`**？现状那个青在暗底上非常刺眼（119 处）。换色是全局视觉变化，需要你看过预览再定。

## 8. 明确不做（防止用力过猛）

- ❌ 逐词着色（「灌木丛」三个字单独绿）—— 只做整句/分句。
- ❌ 块级排版（引文缩进块、短信气泡、表格）—— `<p>` 里塞不进去，会破坏结构。
- ❌ 长 CSS 动画（持续抖动、呼吸灯）—— 打字机每帧重建 DOM，动画会抽搐。
- ❌ 给每个 NPC 分配固定角色色（除非 P5 通过）—— 26 个文件、上百个 NPC，维护成本远大于收益。
- ❌ 用颜色暗示「这个选项是对的」—— 属于信息透明度的平衡问题。
