## 3. 顺带修掉的真 bug：迁移块曾写成死代码

初版把迁移写在 `fillMissingDefaults` 的「补默认值」循环**之后**：

```js
for (const key in defs) if (!(key in state)) state[key] = defs[key];  // 先把 instantNoodle 填成 0
if (!("instantNoodle" in state) && "hasInstantNoodle" in state) { … } // 永远不成立
```

循环先把 `instantNoodle` 填成初值 0，迁移的卫语句恒为假 → 老档玩家手里的那包泡面**凭空消失**（不报错、不崩，典型的静默错误）。
修正：迁移块移到循环**之前**，判据改成 `"hasInstantNoodle" in state`。
`tools/noodle_stack_selftest.js` 里新增一条断言锁住这个顺序（`iMig < iLoop`），防以后再写反。

## 5. 待作者拍板（平衡项，未擅自改数值）

1. **3 包可同时带走 ≈ 3 次「体力回满」可随身储备**。改造前虽然世界库存也是 3 包，但吃完得回全家再拿；现在可以一次囤满带走，远距离行程（张江 / 建平 / 仁济）的续航明显变强。
   - 若要维持原强度，可选：① 泡面由「回满」降为「+5 / +6」；② 世界库存 3 包不改，但吃泡面的 `updateTime(2)` 提到 5~10 分钟（吃一顿要花时间）；③ 维持现状但把泡面作为「可赠送口粮」的定位保留（目前它已在 `FOOD_GIFTS` 里，可送王老师 / 喂猫 / 交路霸）。
2. **旧档迁移对「已吃掉」的判断无误**：旧档 `hasInstantNoodle:true` ⇒ 1 包、`false` ⇒ 0 包，占格数前后一致，背包账目不会凭空多/少一格。**未 bump `SAVE_VERSION`**（走反推迁移，不弃玩家进度）。
