## 二、⚠ 核心问题：现有 3 处「涨容量」入口互斥，实际只能拿到 1 次

现有 3 个给予 `bagVolume +1` 的场景，**全部用 `!hasBag` 做闸门**，且**全库没有任何一处把 `hasBag` 重置回 `false`**（唯一相关的是 core.js:715「丢下帆布包」，但它要求 `hasBag` 为真才显示，代价是掉容量，玩家不会主动点）。

| # | 场景 | 文件:行 | 物品名 | 闸门 | 是否消耗时间 |
| --- | --- | --- | --- | --- | --- |
| 1 | 安盛街-文具店铁柜 | 安盛街.js:950-953 | 帆布袋 | `!hasBag` | updateTime(15) |
| 2 | 新达汇-2F杂物间-帆布包 | 新达汇.js:3799-3821 | 帆布包 | `!hasBag` | 无 |
| 3 | 三林安居苑-卧室-仔细 | 安居苑.js:1573-1576 | 帆布包 | `!hasBag` | updateTime(1) |

**后果**：三条支线（东明街道内部 / 新达汇 / 安居苑）的玩家拿到任意一个后，另外两个的选项就会因 `!hasBag` 直接消失。**全流程上限 +1，3 → 4 格**，而且这个「唯一机会」还藏在三个不同支线的隐蔽角落——这就是你感觉「机会太少」的根因。

此外 `hasBag` 语义是布尔「是否持有背包」，一旦为真就无法再加。要支持多级扩容，必须改数据结构（见第四节）。

## 四、实现建议：支持多级扩容的数据结构改造

现有 `hasBag` 布尔量无法表达「帆布袋 +1」和「登山包 +2」的叠加。推荐二选一：

**方案一（改动小）—— 追加独立布尔 + 名称记录**

```js
// core.js _variables 新增
hasCanvasBag: false,   // 帆布袋（+1）
hasBackpack: false,    // 双肩包（+1）
hasHikingPack: false,  // 登山包（+2）
bagName: "",           // 当前主背包名称（用于 UI 显示）
```

每个道具的 `effect` 里 `set: {hasXxx: true, bagName: "帆布袋"}, add: {bagVolume: 1}`，闸门用各自的 `!hasXxx`（**不要再用 `!hasBag`**，否则又变成互斥）。

**方案二（改动大但干净）—— 数组式**

```js
bags: [],   // [{id:"canvas", name:"帆布袋", volume:1}, ...]
```

`bagVolume` 改为派生值（`3 + sum(bags.volume)`），需同步改 `checkCondition` 的 computed 注入（参考 `_reactive.computed` 的既有做法）。

⚠ **无论哪种方案，core.js:715「丢下帆布包」和 core.js:97 的 `bagVolume: 3` 初始值都要同步改**；`hasBag` 还有 3 个 showCondition 引用（core.js:715、新达汇.js:3799、安居苑.js:1573、安盛街.js:950），改造时需一并替换。
