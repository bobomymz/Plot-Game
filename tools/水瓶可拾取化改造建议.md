`hasCutter`（美工刀）、`hasDagger`（匕首）、`hasAxe`（斧头）、`hasScrewdriver`（螺丝刀，全图唯一，建平）。

**设计取舍（可直接改）**：
1. 箱盖上那瓶**已开封**的定为**空瓶**（`bottleWater: 0`，文案"剩了半瓶，落了灰，你倒掉留瓶"）——保证「有工具 = 拿到水，没工具 = 只拿到容器」的差异化，同时没工具的玩家也不至于空手。**想给成半瓶水，把该节点 `bottleWater` 改成 1 即可**。
2. 箱装水走**「有瓶→换水、无瓶→取新瓶」双分支**：无瓶时 `itemCount +1` 占 1 格；已有空瓶/毒水时只换水、**不占格**（避免"1 个瓶子数成 2 格"）。持满瓶时该选项不显示。
3. 箱装水与已开封瓶都沿用 `condition: itemCount < bagVolume` + `elseScene: 整理整理`；各节点都补了 `positionAfterOperation`，背包满时能正常回来。

**回归**：`condition_audit 0/0`、`scene_fn_selftest 0 异常`、`bottle_pickup_selftest 72/0`、其余套件全绿。
**顺带修掉 2 个既有问题**（非本次引入，见 §6 末尾）。

## 2. ~~强烈建议改造（4 处）~~ → 已全部实施（见 §0）

### R1 · 仁济南院-特需病房-病床 ——「瓶冰凉、没开封的脉动」 ✅
- **位置**：`story/仁济南院.js:1947-1962`（节点 `仁济南院-特需病房-病床`）
- **原状**：只有两个选项——「当场喝掉」（→ `-功能饮料`，体力+1）/「算了，放回去」。瓶子写得很诱人（"瓶子还凉"），但**只能喝掉，拿不走瓶**。
- **改法**：加第三个选项「连瓶一起收进背包」→ **带水瓶**。
- **收益**：把"一次性食物"升级成"容器 + 水"，是候选池里**唯一能一次给到「带水瓶」**的改造点。仁济是中期大图，且该图**当前完全没有水瓶来源**。

### R2 · 新达汇-电梯厅贩卖机-翻找 ——「落货口里几个空矿泉水瓶」 ✅
- **位置**：`story/东明街道/新达汇.js:1082-1097`（节点 `新达汇-电梯厅贩卖机-翻找`）
- **原状**：文本明写「落货口里堆着几个矿泉水瓶，全是空的，瓶盖却一只只拧好」，但玩家伸手翻找**只拿到旧钞票和跑气可乐**，再翻一次（`-空手`）还是"没别的"。全库最典型的**「写了道具却拿不到」**挫败点。
- **收益**：文本与机制对齐；新达汇本身是枢纽，2F 卫生间、4F 后厨都能接水（**都是毒水**）——形成「捡瓶 → 自己判断水质 → 接水」的闭环。

### R3 · 建平-挹芬楼-3F-高一教室 ——「桌缝里还夹着一只空水瓶」 ✅
- **位置**：`story/建平中学.js:3234-3263`（节点 `建平-挹芬楼-3F-高一教室`）
- **收益（这条最有价值）**：激活建平**已有但缺前置**的玩法 —— `建平-弘渊楼-2F` 的「把保温杯里的水灌进水瓶」需要 `hasBottle && bottleWater == 0`（`建平中学.js:2372`）。**原本玩家若没带空瓶进建平，这条支线选项根本不出现。**
- ⚠ **已确认的副作用**：建平桌面保温杯里的水**全部是饮水机的水、全部含甲基汞**（`建平中学.js:2329` 注释："两只杯子都有毒"）。给空瓶会**提高玩家踩毒水陷阱的概率**。该节点文案已写成中性提示（"哪台饮水机还能出水、那水能不能喝——得你自己判断"），不主动误导。

### R4 · 新达汇-1F后勤仓库 —— 原本是「死场景」 ✅
- **位置**：`story/东明街道/新达汇.js:3750-3760`（节点 `新达汇-1F后勤仓库`）
- **原状**：文本写「货架上堆着…几箱矿泉水。矿泉水箱上放着一瓶已经开封的」，但**只有一个「离开」选项，零交互**。

## 5. 顺带发现：保温杯系统（另一套容器，供参考）

## 6. 实现须守的坑（改代码前务必看）

1. **拾取四件套**（照抄现有 5 个拾取点）：
   ```js
   condition: "itemCount < bagVolume",
   effect: { set: { hasBottle: true, bottleWater: 0, waterToxic: false, _hongBottleLabel: false }, add: { itemCount: 1 } },
   elseScene: "整理整理"
   ```
   只有老洪标签瓶才 `_hongBottleLabel: true`。
2. **`elseScene` 不能省**：现有全部拾取点都写了 `elseScene: "整理整理"`，背包满时才不会卡住。
3. **丢弃／送人时必须同步清三个附属变量**（`bottleWater` / `waterToxic` / `_hongBottleLabel`）——漏清会出现"瓶没了但 `bottleWater` 还是 1"的幽灵状态。参考 `core.js:615` 与 `上实南校.js:879` 的写法。
4. **持有判定只有 `hasBottle` 一个**，闸门一律用 `!hasBottle`，不要引入新变量。
5. **`bottleWater` 只是 0/1 两态**（0=空瓶，1=有水），没有"半瓶"档。想表达"半瓶水"就用 `1` + 文案描述。
6. 改完必跑：`node tools/condition_audit.js`（期望两个 0，漏声明变量会让选项**直接不显示**）；
   重新出清单：`node tools/bottle_scan.js`。
7. **函数式 `condition` / `nextScene` 不在 `condition_audit` 覆盖内**（它只审字符串表达式）。这类写法必须用
   `node tools/scene_fn_selftest.js`（全库函数冒烟，0 异常）和 `node tools/bottle_pickup_selftest.js`（水瓶机制 72/0）验证。
8. **新增场景节点必须补 `positionAfterOperation`**：`整理整理` 的"不丢，谢谢"走 `nextScene: "{positionAfterOperation}"`，
   不设就会跳进空场景。参考 `金谊广场-4F` 在场景 `onEnter` 里设 `set: { positionAfterOperation: ... }`。
9. **在 core.js `_variables` 增删行后**，`tools/stamina_report.py` 的 `KNOWN_SITES` 里 core.js 区间要整体平移，
   自测里的合成行号（`core.js:390` / `story/core.js:1165`）也要同步改，否则来源归因和自测会失效。

## 7. 平衡说明（已与作者确认）

原本担心"来源 5 ≈ 给水 5，加瓶即降难度"，但作者已明确：**联华超市与长者食堂都可多次打水**（长者食堂有饮水机、上限 `_waterDispenserUses` 10 次），
所以水瓶从来不是硬约束，**真正的难度来自往返赶路的时间与体力消耗**。因此本次加瓶是可接受的，不必上调给水次数。

仍需留意的一点：**新达汇全图没有干净水源**——2F 卫生间与 4F 后厨接的都是自来水（`waterToxic: true`）。
所以 R2/R4 新增的水瓶在新达汇本地只能装到**毒水**，实际是强化了"毒水陷阱"的设计，而不是给出一条本地的补水捷径。
