## 一、引擎语义（先对齐口径）

`engine.js:917` / `966`：

```js
if (choice.showCondition && !checkCondition(choice.showCondition, gameState)) return;  // 不渲染
const condMet = checkCondition(choice.condition, gameState);
if (!hasElse && !condMet) return;              // 无 elseScene → 不渲染
// 有 elseScene → 渲染，点击后 condMet 为假则跳 elseScene
```

| 写法 | 效果 | 语义 |
|------|------|------|
| `showCondition` 含 `_visit[...]` | 未去过 → **选项不存在** | ✅「去过才解锁」 |
| `condition` + `elseScene` | 未满足 → **选了就死** | ⚠ 死亡陷阱（故意让玩家踩） |
| 什么都不写 | 永远可点 | ❌ 未去过也能"凭空传送"过去 |

`_visit` 由 `engine.js:1143` 在每次 `renderScene` 时按**场景 ID** 自增，所以「去过」的正确键名 = 玩家实际踏进过的那个场景名。

## 三、发现的问题

### P0-1 `_visit['小超市']` 是悬空键 → 联华超市过夜**永久不可达** ✅ 已修

- `story/夜晚剧情.js:98`：`showCondition: "... && _visit['小超市'] > 0 ..."`
- 全库**没有**任何场景 ID 叫 `小超市`。货架场景真名是 `联华超市`（`东明街道路径.js:731`，`onEnter` 已设 `currentPos: "联华超市"`）。
- 后果：该键恒为 `undefined` → 条件恒假 → 选项永不渲染。**连带 `过夜-小超市`、`结局-过夜-小超市暴露` 两个节点成为孤儿**（图报告里它们只有入边、实战走不到）。
- 修法：`_visit['小超市']` → `_visit['联华超市']`。

### P0-2 其余 3 个悬空 `_visit` 键（本次顺带扫描发现，均非过夜系统）✅ 已修

| 悬空键 | 出现位置 | 应为 | 后果 |
|--------|---------|------|------|
| `_visit['4F电梯厅']` | `新达汇.js:2281/2282/2291/2297/2303/2309`（6 处） | `新达汇-4F电梯厅`（`新达汇.js:2587`） | 4F 污水描写分支 + 4 个选项的 `showCondition` 恒假，**4F 一段剧情与选项全部失效** |
| `_visit['全家-喝饮料腹泻']` | `全家和公交站.js:74` | `结局-全家-喝饮料腹泻`（`全家和公交站.js:370`） | `!_visit[...]` 恒真 → 防重复触发的闸门失效 |
| `_visit['金谊广场-B1奥乐齐-搜刮']` | `金谊广场.js:991` | `金谊广场-B1奥乐齐-搜刮-吃完`（`金谊广场.js:1270`） | 与 `金谊广场-3F-幸存者-分食物` 的互斥判断失效 |

> 这正是项目备忘里挂着的「9 个 `_visit` 悬空场景 ID」待办 —— 本次定位到 4 个，其余未在本次范围内。

### P1-1 深夜食堂「锁好门」会让过夜选项变成死亡陷阱 ✅ 已修

`新达汇.js:3311–3315`「锁好门」的效果是 `set: { _yorozuyaUnlocked: false }`，而 `_yorozuyaUnlocked` 字面意思是**门当前没上锁**。
于是：带钥匙的玩家正常开门 → 锁好门离开 → 夜里再选「去东区哥哥的深夜食堂过夜」→ `condition` 假 → 死亡结局，且结局文案写"你没有钥匙"——**与玩家实际持有 `hasDoorKey1` 矛盾**。
过夜门槛应改为 `_yorozuyaUnlocked || hasDoorKey1`。
