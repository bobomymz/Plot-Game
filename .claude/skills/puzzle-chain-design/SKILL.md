# 解密链设计/优化

核心原则：**难度来自杠杆组合，新颖性来自主机制错位，预算靠非背包奖励兜底。**
"高难度"不是形容词——必须能拆成具体杠杆；"和以前不一样"不是换皮文字——锁的原理/信息载体/风险类型至少一项错开。

## 两个入口

**设计新链**：读区域设定（设计细节.md/核心设定3.0.md）→ `node tools/chain_audit.mjs` 盘库存 → 定奖励等级和杠杆组合 → 查下方套路清单确认错位 → 出**一页纸方案**给用户过目 → 过了再落码 → 走 story-testing 验证。

**优化旧链**：`node tools/chain_audit.mjs`（看该物品拾取/引用分布）→ 按下方检查表逐项打分 → 出改法方案 → 用户过目 → 落码验证。

**方案先行，不直接落码**——剧情质感由用户把关，skill 只出结构。

## 第一步：奖励定级（决定难度预算）

| 级 | 含义 | 例 | 杠杆要求 |
|---|---|---|---|
| T0 | 故事真相情报 / 终局道具 | 仁济太平间报告、王萍手机 | ≥3 根杠杆，跨 ≥2 类 |
| T1 | 优质生存物资 / 强力战斗道具 | 斧头、手枪、书包(5格) | ≥2 根杠杆 |
| T2 | 便利品 / 普通道具 | 饼干、香肠 | ≤1 根杠杆，别过度设计 |

## 第二步：选杠杆（8 种，含项目已有范例）

| 杠杆 | 已有范例 |
|---|---|
| 战斗门槛 | 闪色战斗、QTE 缠斗、警局武器室 |
| 前置物品 | 润滑油→自行车、车钥匙→轿车、防毒面具→仁济污染区 |
| 多步操作 | 防毒面具计数链（拾取/消耗/重置三态） |
| 信息门槛（玩家自己记线索） | 存款凭条、车库接线图（弱光源看不清细节） |
| 时间窗 | 周师傅 Day2 12:00–12:30 联华仓库偶遇 |
| 状态门槛 | chasedByZombies / strength / 雨天 / isNight |
| 经济门槛 | 手机电量（无充电=终局）、防毒面具次数、武器耐久、背包空间（拿奖励得先丢东西） |
| 风险/不可逆 | 水有毒、武器会断、开枪引尸潮、五金店暗道 |

**软硬门槛选择**（细化见 CLAUDE.md「showCondition vs condition」）：坑玩家用软门槛（选项常驻 + `condition`+`elseScene`，能选但代价惨）；纯道具链用硬门槛（`showCondition` 藏选项）。战斗/QTE 失败照旧死得难看——难度哲学不因链长而软化。

## 第三步：查套路清单（新颖性检查）

已用主机制（**新链必须在"锁的原理/信息载体/风险类型"至少一项上错开**，换皮文字不算）：

- 钥匙链：hasDoorKey1（全家员工通道）、hasCarKey（轿车/新达汇B1）、hasKey502、hasCommitteeKey、hasEbikeKey、hasKeyRing（建平老吴钥匙串）
- 修理解锁：润滑油→生锈自行车
- 撬砸解锁：铁管/斧头 vs 铁栅栏门（联华仓库、上实天桥）
- 计数经济：防毒面具（4拾取点/6消耗点/部分重置）、手机电量
- 记忆挑战：记忆闪色战斗、密码/数字输入框
- 光源分级：强黑暗只认手电（金谊B2/五金店），弱黑暗手机也行（菜市场通道）
- 电力门槛：银行金库"通上电再回来"（已伏笔，未实装）
- 跨区域联动：五金店暗道线索→周师傅、民防设施物资区
- 宏观剧情套路：医院真相线（仁济）、学校营救线（建平）、集市交易（菜市场）、路霸搜身（反派NPC）

**最便宜的双重杠杆是跨区域联动**——旧区域的线索/物品开新区域的锁，同时满足新颖性和物品预算。维护责任：每落地一条新链，把主机制追加进本清单。

## 物品预算与奖励分层

- 硬红线：新区域**占背包物品 ≤10**；目标 3–5。`chain_audit.mjs` 末尾的"每文件独占引入"表直接查。
- 非背包奖励优先当大头：**情报**（真相线索，零背包成本——T0 链难度高又不吃预算的解法）、场景解锁（捷径/安全屋/电梯）、NPC 关系、能力（交通工具/背包升级）、状态回复。
- 记忆奖励只收玩家本人危机前回忆（既有约定）；真相一律走**情报**不走记忆。
- 复用潜力看 chain_audit"引用场景数"：引用多的物品（铁管19、手电35）是万能钥匙素材；引用≈拾取的加"⚠死道具"备注——要么给它新用途，要么别再写同类。
- 武器类多拾取点是**预期行为**（断了解锁回原点再拿），不算预算超支的理由去写新武器。

## 贴合设定三问（方案里必须逐条回答）

1. **为什么这东西还在？** 危机才 Day1–5，谁没拿走/拿不走——太重需要交通工具？在丧尸堆里？需要专业知识才认得值钱？"没人拿走"必须有答案。
2. **锁为什么打不开？** 匹配场所专业逻辑（金库→电力/专业设备；学校→保安室/班主任；药房→电子锁/药品柜），不许"恰好锈死"。
3. **丧尸为什么挡在这？** 位置合理性 + 既有红线：数日尺度环境描写、NPC 知识门控（`_visit` 先交互后引用）。

## 难 ≠ 烦红线

- 绕路每段必须自带新内容（遇敌/lore/新场景）；**纯跑腿段 ≤2**，超过就在中途放捷径或次级奖励。
- 多步操作每步要有信息增量——玩家做完这步应该比上一步多知道点什么。
- 失败可以残酷（死亡结局是卖点），但来回跑图不算难度。

## 一页纸方案模板

```markdown
## <链名>（奖励：xxx，定级 T_）
- 区域/入口 → 终点：
- 杠杆组合：战斗(__) / 前置物品(__) / 多步(__) / 信息(__) / 时间窗(__) / 状态(__) / 经济(__) / 风险(__)
- 主机制与套路清单的错位点：
- 设定三问：为什么还在？为什么锁着？丧尸为何在此？
- 分支：无前置 elseScene → ___；战斗/QTE 失败 → ___（共享死亡结局优先）
- 路径：A → B → C → D（纯跑腿段数：__）
- 新增占包物品 __ 个 / 复用既有 __ 个（chain_audit 核对）
```

## 工具：`node tools/chain_audit.mjs [区域]`

输出 `tools/chain-report.md`：每个 hasXxx 的拾取点/移除点/引用场景数/占包判定 + 每文件占包物品数（预算表）+ 死道具/未注册警告。原理：函数源码扫描 + 基础状态求值（抓 `updateTime(N,{...})` 闭包参数里的拾取），局限性——动态拼接赋值抓不到，"?"占包判定人工核对。

## 落码与验证

- 写法规范全部走 CLAUDE.md（守卫三件套、全图唯一物品多拾取点守卫、效果对象单操作符合并、变量注册）。本 skill 不重复。
- 验证走 story-testing skill：`lint_story.mjs` 清 [E] → `graph_audit.mjs <区域>` 看链节点连通 → 必要时 e2e 传送走一遍"有前置/无前置"两路。

## 维护

- 落地新链 → 主机制追加进上方套路清单
- chain_audit 误报/漏报新写法 → 修工具并在工具头注释补已知局限
- 分级/预算规则调整 → 改本文件，勿散落到各区域文件
