# 新区域剧情设计（编排器）

核心原则：**区域是编排单位，不是内容单位。** 地理结构走 geo-optimization、解密链走 puzzle-chain-design、验证走 story-testing——本 skill 只做三件事：定阶段门、补区域级跨切面（定位差异/入口契约/时间预算/DoD）、在对的时机调对的工具。

**例外：小区域（≤15 场景的补给点/便利店级地点）不走全流程**——阶段1+2 合并成一页方案直接落码，阶段4 的 area_check 照跑。

## 四阶段总览

| 阶段 | 产出物 | 主要工具/skill | 确认门 |
|---|---|---|---|
| 1 定位 | 区域方案 v1（`docs/区域方案-<名>.md`） | chain_audit + 三份设定文档 | 方案过用户目 |
| 2 骨架 | 可跑的占位骨架（枢纽+跳转+过夜分支） | graph_audit + geo-optimization | 骨架图过用户目 |
| 3 主线 | 一条走通的核心主线 | puzzle-chain-design（逐链） | area_check 全绿 + e2e 主线走通 |
| 4 迭代 | DoD 勾完的区域 | area_check + story-testing | DoD 清单收口 |

方案落盘 `docs/`（仓库内，AutoPushGame 每小时兜底）——会话 compact 后靠它续命，**别只存在对话里**。

## 阶段1：读与盘 → 定位

**读**：设计细节.md（路网/出城衔接）、核心设定3.0.md、人物档案.md（NPC 去向）；grep 新区域名/NPC 名查邻区已埋的伏笔和衔接口。
**盘**：`node tools/chain_audit.mjs`（全图）——引用场景数高的物品（铁管/手电）是可复用素材；看各文件预算水位。

**方案必答四件套**：

| 项 | 判定标准 |
|---|---|
| 一句话定位 | "仁济=真相线高风险医疗区"级别的锚 |
| 差异声明 | 对下方差异矩阵**逐行**比对，叙事定位或主打机制至少一项错开；同构风险点逐条躲开 |
| 玩家前来的理由 | T0/T1/T2 奖励分布（定级见 puzzle-chain-design） |
| 时间预算 | 玩家第几天能到 · 主线耗时几个游戏小时 · 要不要过夜点（A/B/C 类） |

**入口契约**（骨架期就要定）：从哪个立交/街道/门接进、currentArea 值、夜晚剧情.js 过夜分支、出城路径（高速口子只写"下高速"级模糊表述）。

## 阶段2：骨架先行

地理初稿**直接落成代码**：`story/<区域>.js` 只写枢纽场景（`images/placeholder.png` + 一句话占位 text + choices 跳转）+ index.html 挂 script。然后：

1. `node tools/graph_audit.mjs <区域>` 红线清零（死链/死胡同必须 0；指标判读见 geo-optimization）
2. 过夜分支先挂进夜晚剧情.js——**骨架期就挂，别等填肉**
3. 节点命名 `区域-位置[-子位置]` 分级（新达汇是标杆）

**为什么骨架先行：改图成本在占位期最低**——地理"后续反复修改"是必然的，20 个占位节点比 200 个成品场景好改一个数量级。
**门：骨架图（graph-report 的 mermaid）过用户目。**

## 阶段3：核心主线

- **只做一条主线**，次要剧情全部留给阶段4——贪多必烂尾。
- 每条解密链单独走 puzzle-chain-design：一页纸链方案 → 用户过目 → 落码。
- **战斗密度**：新区域配额对标同体量区域（仁济 5 闪色/1 QTE、上实南校 0/3），别对标最密的张江(14闪色)/建平(16 QTE)/新达汇(28 QTE)——那是成熟期多轮迭代叠加的结果。方案里写本区域配额，超了砍。
- **场景图预算**：标出必须新图的节点数——图是用户生成的，这是用户的工作量；可复用全局图/邻区图的标注。
- **NPC 改动同步写回人物档案.md**：允许小改，改了不写回 = 文档永久过时。

**门：`node tools/area_check.mjs <区域>` 三连全绿 + e2e 从入口真实状态（不 teleport 造前置）走通主线，交用户测可玩性。**

## 阶段4：迭代循环

用户反馈三分类路由：

| 反馈 | 动作 |
|---|---|
| bug | story-testing 决策表选组合修 |
| 结构问题（绕路/死角/节奏） | graph_audit 定位 + geo-optimization 七步流程 |
| 新剧情（次要线/新链） | 小补给点直接写；成链走 puzzle-chain-design |

- 每轮收尾必跑 `node tools/area_check.mjs <区域>`，全绿才算这轮完。
- 引入新占包物品后复查预算 ≤10（chain_audit 预算表）。
- 迭代记录（做了什么/用户反馈了什么）追加进区域方案 md。

| 上海市区路径 | 城际连接 | 交通选路、无交通工具即死门 | — |

**已知同构风险（差异声明必须逐条躲开；2026-09-22 盘点）**：

1. 双商场（新达汇/金谊）：现靠"半开放+记忆密集 vs 全开放探索"拉开，新增商业体必须再找新轴。
2. 双校园营救（上实南校/建平）：循环同为"清楼→救人→撤离"，第三个校园必须换循环结构。
3. 三个限次交易NPC（方姐/赵广成/郎中）：交易规则要有区分度，别再写"给食物换东西"。
4. 搜刮容器类偏多（安居苑入户/新达汇车库/地铁站/药房）：机制各有变化，玩家体感靠**奖励类型**拉开。
5. 安全屋密集：新增过夜点要和既有收益梯度错开，别造同质安全屋。

## 区域 DoD（收口逐项勾）

- [ ] `node tools/area_check.mjs <区域>` 三连全绿（lint [E]=0 · graph 死链/死胡同 0 · chain 预算≤10、无新死道具）
- [ ] 过夜分支挂了；整理整理入口按 A/B/C 类布点
- [ ] e2e 从入口**真实状态**走通主线（不 teleport 造前置）
- [ ] project-rules 过一遍（方位词/引号/NPC门控/数日尺度/武器点名）
- [ ] 人物档案.md / 设计细节.md 有小改的已写回
- [ ] 差异矩阵追加本区域行；同构风险点若有新增，补进去

## 维护

- 新区域落地 → 差异矩阵追加一行；发现新的同构风险 → 追加进风险清单
- 阶段门/DoD 漏项 → 改本文件，勿散落到区域文件
- 战斗密度参照数过期 → 重盘：`grep -c "initMemoryGame(" story/*.js` 剔除 utils.js 里的定义（当前全图 41 闪色/86 QTE，2026-09-22）
