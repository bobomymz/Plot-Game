# 优化地理结构

针对半开放区域（对应现实建筑物/街区）的节点连接网络重构。核心信念：**AI 生成的节点网络为了迎合解密/战斗剧情，天然偏向放射形/链形、与现实矛盾、只考虑来路**——本技能用数据把这个偏向暴露出来，再按原则修正。

## 工作流程（七步，④后有一个用户确认闸门）

```
① 提取现状 —— 跑 tools/graph_audit.mjs，得邻接表/mermaid图/指标
② 诊断 —— 对照"量化红线"逐条判读，列问题清单（区分真问题/灰区/豁免）
③ 现实检索 —— 查真实建筑结构，或列清单让用户去搜
④ 方案 —— 简化分档 + 新图(before/after mermaid) + 改动清单 → 【用户确认闸门】
⑤ 执行 —— 改 story 文件，同步"配套更新清单"
⑥ 复检 —— 重跑脚本对比指标，死链必须为 0
⑦ 可选 —— Playwright 冒烟走一遍新区域
```

**闸门是硬性的：没出 before/after 图、用户没点头，不许改 story 文件。**

## ① 图审计脚本

```powershell
node tools/graph_audit.mjs              # 全局总览：每文件指标 + 死链 + 跨文件边
node tools/graph_audit.mjs 新达汇       # 区域详报（文件名含该串的文件合成一组）
node tools/graph_audit.mjs 安居苑 --labels  # 边上标注选项文字
```

报告输出到 `tools/graph-report/<区域>.md`（含 mermaid 图，VSCode/GitHub 直接渲染）和同名 `.mmd`。

脚本机制（读数时要知道的局限）：
- 函数型 choices 用 5 个状态变体（初始/全真/全假/夜晚/全访问）调用求并集，极端状态组合的分支可能漏。
- `{_var}` 动态跳转（如 `_elevatorTarget`）会展开为 effect/onEnter 里赋过值的目标（候选 ≤30）；`positionAfterOperation` 这类全图回跳变量不展开。
- 全局触发器进入的结局节点会标注"非孤岛"。

### 指标判读（2026-09-20 用新达汇 192 节点校准过）

| 指标 | 红线 | 判读 |
|---|---|---|
| 死链 | 必须 0 | 修就完了 |
| 死胡同（无出边非结局） | 必须 0 | 玩家会卡死 |
| 连通块 | 核心=1 | 孤岛=残留节点或漏接边（触发器进入的结局除外） |
| 环路数（环秩） | 街区级核心区 ≥2 | 0=纯树形。真实环秩可以很高（新达汇 109），不是越高越好，对照现实结构判断 |
| 真割点 | 看部位 | 门/楼梯间/大门=天然咽喉，正常；**走廊中部**是真割点=结构太线性，优先修 |
| 单出口·非回路型 | 逐个看 | 大多是"动作结果→另一场景"的正常链，少数是漏接边 |
| 选项数 ≥6 | 逐个看 | 电梯厅/走廊枢纽超 8 个考虑拆子节点 |
| 路由/内容混合 | 应为 0 | 移动≥3 且 动作≥3 的节点要拆 |
| 跨层选层模式 | 楼梯不行，电梯可以 | 见下"楼梯与电梯" |

**豁免白名单（不作为问题上报）**：
- `整理整理` 及其子节点（物品管理系统，选项多、单边返回都是设计使然）
- `结局-*` 节点（无出边正常；只查入边是否为 0 且非触发器目标）
- 动作结果节点（`-翻找`/`-吃剩菜`/`-躲藏` 这类单边返回或单链下行的）
- `start`、`travelScene` 过场节点（`-途中`/`前往X-N`）

## 诊断原则补充

- **只考虑来路**的典型症状：区域出口边全部指回入口方向，出边/入边严重不对称（总览表可见）。诊断时对比"进入区域的边数"和"离开区域的边数"。
- 放射形症状：单一枢纽节点真割点脱离块特别大（如脱离 10+ 节点），其余节点都是单出口。

## ③ 现实贴合

本项目地点全是真实上海浦东地点（新达汇/仁济南院/建平中学/三林路…），按此顺序检索：

1. **商场/医院**：大众点评楼层导览、高德/百度地图室内图、官方公众号推文
2. **学校/小区**：房产网站平面图、新闻配图、百度贴吧
3. 查不到 → **列清单明确请用户去搜，查不到就说查不到，禁止编造结构**

**简化三档**（④方案里先和用户一起划档，别默认全网状）：

| 档 | 适用 | 结构要求 |
|---|---|---|
| A·核心区 | 解密/战斗主线 | 贴合现实 + 环路完整 |
| B·次区 | 补给/支线 | 主路+辅路，结构对但房间可合并 |
| C·装饰区 | 路过性质 | 链形允许，text采用环境叙事 |

## 重构设计规则

1. **网状分级**：同层/同区内部求环路（走廊成环、多出口房间）；跨层/跨区允许收窄到咽喉点（楼梯间/门厅/连廊）——咽喉是 QTE 追击、堵路事件的剧情资源，别拆。
2. **路由节点 vs 内容节点二分**：
   - 路由节点（路口/门厅/走廊拐角）：只放移动选项，绝对方位词，移动选项 ≤5（引擎会打乱顺序，太多会懵）
   - 内容节点（房间/摊位/事发现场）：搜刮/战斗/对话，移动选项 ≤2（一般就"离开"）
   - 混合（移动≥3 且 动作≥3）→ 必拆
3. **楼梯与电梯**：
   - **楼梯**：逐步节点（1F楼梯-2F楼梯-3F楼梯链），例外=楼层≤3 且楼梯间无剧情。无剧情楼层写薄节点（2-3 个选项、一句话 text），剧情只在有事件的楼层展开
   - **电梯**：选层直达是**合理**的（现实如此），用 `_elevatorTarget` 变量路由模式（各层电梯厅设变量 → 共用"电梯途中"节点 → `{_elevatorTarget}` 插值跳转），参考新达汇实现
4. **门单独成节点**：走廊-门-房间结构。门节点天然挂锁状态 flag、撬锁走 `useHeavyTool` 耐久规则、双向复用同一节点。
5. **节点命名**：`区域-位置[-子位置]` 前缀分级（新达汇的 `新达汇-3F北走廊中` 是标杆），楼层/区位段要一致。
6. 必要时可加入冗余地点

## ⑤ 执行时的配套更新清单（漏一项就出 bug）

- [ ] 新增开放区域 → `夜晚剧情.js` 补过夜分支
- [ ] 枢纽场景补 `🎒整理一下物品` 入口（带 `positionAfterOperation` 返回点）
- [ ] 新开放场景的物品守卫三件套（`!hasXxx` / `!visitXxx` / `condition+elseScene`）
- [ ] 新移动边挂 `updateTime`（>6 分钟自动进疲劳计费）；路网节点 `showZombies`、户外 `showRain`
- [ ] 选项用绝对方位词（"往北走"），不用"继续走/往回走"
- [ ] 新变量注册进 core.js `_variables`（含 `_xxxTarget` 路由变量）
- [ ] **改名时全量 grep**：`nextScene` / `elseScene` / `onTimeout` / `timeoutScene` / `positionAfterOperation` 的值 / effect 函数里的 `v._xxx = "场景ID"` 赋值——最后两个最容易漏

## ⑥ 复检

```powershell
node tools/graph_audit.mjs <区域>   # 对比 before/after：环秩↑、真割点↓、死链=0、死胡同=0
```

指标变差或持平要能解释原因（如"环秩降了但换来了现实贴合"）。改动大时用 Playwright 冒烟：起 `npx http-server -p 8630`，走一遍新区域主路径。
